# Azure DR設計とフェールオーバー ワークショップ

## 1. 概要

- **想定時間**: 3時間（休憩・ハンズオン込み）
- **対象者**: Azureの基本操作、Webアプリ、ネットワークの基礎を理解しているインフラ／クラウド担当者
- **形式**: 講義、デモ、ハンズオン、障害注入、振り返り
- **主なサービス**: Azure Front Door、App ServiceまたはAzure Functions、Azure Monitor、Azure Storageなど

## 2. 到達目標

ワークショップ終了後、受講者が以下を実施できることを目標とする。

- 可用性、バックアップ、DRの違いを説明できる
- RTO／RPOから必要なDR方式を検討できる
- Azureの代表的なマルチリージョン構成を理解できる
- Azure Front Doorを使ったリージョン障害時の切り替えを体験できる
- フェールオーバーだけでなく、フェールバックと定期的なDRテストを含む運用を検討できる
- アプリケーション、データ、ネットワーク、運用手順を一体としてDR設計できる

## 4. 講義内容

### 4.1 DRの基本概念

- 高可用性とDRの違い
- バックアップとDRの違い
- 可用性ゾーン障害とリージョン障害
- RTO：復旧までに許容できる時間
- RPO：許容できるデータ損失量
- 復旧ポイントと復旧手順
- 共有責任モデル
- コントロールプレーン障害も考慮した復旧

### 4.2 DRパターン

| パターン | 概要 | コスト | RTOの目安 |
|---|---|---:|---:|
| Backup & Restore | バックアップから環境を再構築する | 低 | 長い |
| Pilot Light | 最小限の基盤を別リージョンで待機させる | 低～中 | 中～長 |
| Warm Standby | 縮小構成を別リージョンで稼働させる | 中 | 中～短 |
| Active-Passive | セカンダリ環境を待機させる | 中～高 | 短い |
| Active-Active | 複数リージョンで常時処理する | 高 | 最短 |

### 4.3 Azureサービス別の検討事項

#### ネットワーク／エントリーポイント

- Azure Front Door
- Traffic Manager
- Application Gateway
- DNS TTL
- ヘルスプローブ
- Private Link利用時の考慮事項
- 手動切り替えと自動切り替え

#### コンピュート

- App Service／Azure Functionsの複数リージョン配置
- VMとAzure Site Recovery
- AKSの複数クラスター構成
- コンテナーイメージ、設定、シークレットの複製
- Infrastructure as Codeによる再現性

#### データ

- Azure SQL DatabaseのFailover Group
- Cosmos DBのマルチリージョン構成
- Azure StorageのZRS／GZRS／RA-GZRS
- PostgreSQLなどのレプリケーション
- データレプリケーションの遅延と整合性
- アプリは切り替わったがデータが利用できない問題の防止

#### 運用

- DRランブック
- 切り替え権限と承認フロー
- シークレット、証明書、RBACの複製
- 監視とアラート
- DRテストの実施頻度
- フェールバック手順

## 5. ハンズオン：Azure Front Doorによるリージョンフェールオーバー

### 5.1 演習の目的

2リージョンに配置されたWebアプリをAzure Front Doorの背後に構成し、ヘルスプローブを利用したリージョン間のフェールオーバーとフェールバックを確認する。

### 5.2 想定構成

```text
                         Azure Front Door
                          /             \
                         /               \
            Primary App Service     Secondary App Service
               Region A                 Region B
```

アプリケーションは、表示画面にリージョン名を表示する簡易Webアプリとする。データストアは演習対象外として簡略化し、アプリケーションの切り替えに集中する。

### 5.3 演習手順

1. 2リージョンに配置されたWebアプリへ個別にアクセスする
2. 各アプリのヘルスチェックエンドポイントを確認する
3. Azure Front Doorのプロファイルとエンドポイントを作成する
4. Primary／Secondaryのオリジンを登録する
5. オリジングループを作成する
6. ヘルスプローブを設定する
7. 優先度ベースのルーティングを設定する
8. Front Door経由でPrimaryへ接続されることを確認する
9. Primary側に安全な障害を発生させる
10. ヘルスプローブの状態変化を確認する
11. Secondaryへの切り替えを確認する
12. Primaryを復旧する
13. Primaryへのフェールバックを確認する
14. 切り替え時間を測定し、想定RTOと比較する

### 5.4 期待結果

- 正常時はFront DoorからPrimaryリージョンへ接続される
- Primaryのヘルスプローブが失敗すると、Secondaryリージョンへ切り替わる
- Primary復旧後、設定に応じてPrimaryへフェールバックできる
- 切り替え時間を実測し、ヘルスプローブ間隔やアプリの復旧時間との関係を説明できる

## 6. 障害注入、復旧、フェールバック

安全性と再現性を高めるため、以下のいずれかの方法で障害を注入する。

- Primaryアプリを停止する
- ヘルスチェックエンドポイントだけを異常状態にする
- Front DoorからPrimaryへのアクセスを一時的に拒否する
- アプリ設定で障害モードを有効化する

リソース削除やデータ破壊による障害注入は行わない。

### 確認項目

- 障害発生時刻
- ヘルスプローブが異常と判定した時刻
- Secondaryへ切り替わった時刻
- Primary復旧時刻
- Primaryへフェールバックした時刻
- 利用者影響時間
- 想定RTOとの差分
- ログ、メトリック、アラートの有無

## 7. 発展課題

時間に余裕がある受講者向けの追加課題。

- Active-Passiveから重み付けルーティングへ変更する
- セッション状態を持つアプリで切り替え時の問題を確認する
- ヘルスプローブのパスや間隔を変更する
- Azure Monitorアラートを設定する
- 手動フェールオーバー手順をランブック化する
- RTO／RPOが異なる3つのシステムにDR方式を割り当てる

## 8. 事前準備

### 8.1 受講者

- AzureサブスクリプションへのContributor相当の権限
- Azure Portalを操作できること
- App Service、Functions、VNetの基本知識
- Azure Cloud ShellまたはAzure CLIを利用できること
- Webアプリへアクセスできるブラウザー

### 8.2 講師

- 受講者ごとのリソースグループ
- 2リージョンのサンプルWebアプリ
- `/health`エンドポイント
- Azure Front Doorの初期構成、または展開用テンプレート
- 障害注入用の設定
- フェールオーバー／フェールバック確認シート
- リソース削除手順

## 9. 運営上の注意

- 2リージョンのWebアプリとFront Doorは事前展開を推奨する
- DNS伝播が必要なカスタムドメインや証明書設定は、時間短縮のため演習対象外とする
- Front Doorのプロビジョニング時間を考慮し、講義中に作成を開始する
- アプリケーションの切り替えとデータレプリケーションを混同しないように説明する
- 実際の本番DRでは、データ、シークレット、証明書、RBAC、監視も複製対象になることを補足する
- 演習終了後に、作成したリソースを削除する手順を案内する
