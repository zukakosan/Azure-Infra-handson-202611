# IaaS：Azure Site RecoveryによるDRハンズオン

[リポジトリ TOP](../../../README.md)

元リージョン（Region A）のWebサーバーをAzure Site Recovery（ASR）で復旧先（Region B）へ複製し、切り替えと元リージョンへの復帰を体験します。

**下の順番で進めてください。初めての方は「1. 開催前の準備」から、準備済みの方は「2. 当日の教材取得」から始めます。**

操作・確認の目安は約210分です。デプロイや複製などの待ち時間は別途必要です。本番環境ではなく、自分専用の演習環境を使用します。

## 1. 開催前の準備

**開くページ：[参加者用の事前準備](./preparation/00-participant-preparation.md)の1章・2章**

Windows PCにAzure CLI・Bicep CLIを用意し、演習用アカウントでAzureにログインできることを確認します。Git・Visual Studio Code・Azure PowerShell（Azモジュール）は不要です。パラメータの編集には導入済みのサクラエディタを使います。

演習用サブスクリプションを選び、[Azure環境の確認項目](./preparation/00-prerequisites.md)の3章で権限・クォータ・ポリシー・通信条件も確認してください。自分で変更できない制約は管理者へ相談します。

**ここまでの完了条件：** ツールが動き、Azure CLIとPortalにログインでき、演習用サブスクリプションで必要なリソースを作成できる見通しが立った。教材ZIPは当日取得します。

## 2. 当日の教材取得

**開くページ：[参加者用の事前準備](./preparation/00-participant-preparation.md)の3章**

教材をZIPで取得・展開し、PowerShellでリポジトリルート（直下に`BCDR`があるフォルダー）を開きます。サクラエディタで[パラメータファイル](./preparation/infra/main.bicepparam)が開けることも確認します。

**ここまでの完了条件：** 教材の場所を確認する2つの`Test-Path`が`True`になり、パラメータファイルをUTF-8で開けた。

## 3. 初期環境を作る

次の2ページを順に実施します。**00で作成し、01で確認します。Portalで同じリソースを手作業で作成する必要はありません。**

| 順番 | 開くページ | やること・完了条件 |
|---|---|---|
| 00 | [Bicepによる初期リソースの作成](./preparation/00-create-initial-resources.md) | 自分の演習ID・リージョン・パスワードを設定し、変更内容を確認してデプロイする |
| 01 | [デプロイ結果の確認](./exercises/01-verify-deployment.md) | 作成されたリソースを確認し、元VMへBastion Developer経由でログインする |

ここではネットワーク・元VM・Recovery Servicesコンテナー・キャッシュストレージを作成します。**WebページもASRの複製も、まだ設定されていません。** 次の演習で順に設定します。

演習用パスワードはファイルに保存せず、他環境に流用しません。環境変数の削除は、00のデプロイ後の手順で実施します。

## 4. Webページを作り、別リージョンへの切り替えと復帰を試す

**上から1ページずつ実施し、各ページの完了条件を満たしてから次の行へ進んでください。**

| 順番 | 開くページ | やること・完了条件 |
|---|---|---|
| 02 | [ApacheとHTMLの構成](./exercises/02-configure-apache.md) | 元VMにWebページを作り、ブラウザーで表示を確認する |
| 03 | [ASRの構成と初期複製](./exercises/03-configure-asr.md) | 作成済みのコンテナーを使って必要なロールを割り当て、A → Bの複製と復旧ポイントを確認する |
| 04 | [テストフェールオーバーと復旧確認](./exercises/04-test-failover.md) | テスト用ネットワークで復旧VM・Webページを確認し、テストを終了する |
| 05 | [実フェールオーバーとHTML更新](./exercises/05-failover-and-update.md) | 元VMを停止してBへ切り替え、コミット後にWebページを更新する |
| 06 | [逆方向の再保護](./exercises/06-reprotect-to-source.md) | B → Aの複製を設定し、復旧ポイントを確認する |
| 07 | [フェールバックと再保護](./exercises/07-failback-and-reprotect.md) | Aへ戻り、更新したWebページとA → Bの保護を確認する |

VMが起動しただけでは完了ではありません。Webページの内容と、PortalのVM・リージョン・IPアドレスを照合します。複製・再保護が未完了なら先へ進まず、停止箇所と理由を記録してください。待機上限は確保した時間に合わせて決めます。

> 演習中の注意：停止・コミット・再保護の前に対象と必要な承認を確認してください。VMへはBastionで接続し、公開IPへのSSH接続はしません。HTTPの演習ページに秘密情報や業務データを置かず、**ASR構成後に初期環境のBicepを再展開してリセットしないでください。** 実際のリージョン障害は起こしません。本番経路・DNS・外部DB・認証基盤の復旧は対象外です。

## 5. 後片付けする

**開くページ：[08：クリーンアップ](./exercises/08-cleanup.md)**

必要な証拠をVM外へ保存し、保護の解除・依存関係の解除・リソース削除を手順どおりに実施します。継続利用する場合は対象と理由を記録します。

**ここまでの完了条件：** 削除または継続利用の記録が完了し、残存リソースと費用を確認した。VMを停止するだけでは、ディスク・公開IP・ストレージなどの費用はなくなりません。

## 途中で困ったら

[09：よくあるハマりどころとトラブルシューティング](./exercises/09-troubleshooting.md)で該当する症状を確認してください。解決したら、止まっていた手順へ戻ります。
