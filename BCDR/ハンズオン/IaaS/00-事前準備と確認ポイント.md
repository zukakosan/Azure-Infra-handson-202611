# IaaS：事前準備と確認ポイント

[全体・進捗チェック](../01-IaaS-ASRによるDRハンズオン.md) | [Bicepによる初期リソースの作成](./00-Bicepによる初期リソースの作成.md) | [Portalでの初期構築](./01-ネットワークとVMの作成.md)

参加者のWindows PCで、教材の取得と実行環境を準備します。画面とコマンドの結果を確認し、当日の初期構築に備えます。

## 1. 必要なツール

Bicepで初期構築する場合は、次のツールを用意します。

| 項目 | 用途 |
|---|---|
| ブラウザー | GitHub、Azure Portal、Bastion、演習ページを表示 |
| PowerShell | 手元のPCでBicep手順を実行 |
| Azure CLI | AzureへのログインとBicepのビルド・デプロイ |
| Git | 教材をcloneで取得 |

Portalで初期構築する場合は、ブラウザーで教材とAzure Portalを開きます。

ツールの導入は組織の端末管理ルールに従ってください。インストール後はターミナルを開き直します。

- [Git for Windows](https://git-scm.com/downloads/win)
- [Azure CLIのWindowsへのインストール](https://learn.microsoft.com/ja-jp/cli/azure/install-azure-cli-windows)

PowerShellはWindowsのスタートメニューから開きます。パラメータファイルの編集には、普段使っているテキストエディターを使用してください。

## 2. 教材を手元に取得する

### Gitを使う場合（推奨）

PowerShellで、教材を置きたいフォルダーへ移動してから実行します。

```powershell
git clone https://github.com/zukakosan/Azure-Infra-handson-202611.git
if ($LASTEXITCODE -ne 0) { throw 'Repository clone failed.' }
Set-Location '.\Azure-Infra-handson-202611'
```

以降のBicep手順は、この**リポジトリルート**で実行します。次のコマンドが`True`になることを確認します。

```powershell
Test-Path '.\BCDR\ハンズオン\IaaS\infra\main.bicep'
```

### Gitを使わない場合

[教材リポジトリ](https://github.com/zukakosan/Azure-Infra-handson-202611)の **Code → Download ZIP** から取得し、展開します。PowerShellで展開先のリポジトリルートへ移動し、上記の`Test-Path`で確認してください。

## 3. Azure CLIの動作を確認する

Bicepで初期構築する参加者は、手元のPowerShellで実行します。

```powershell
az version
if ($LASTEXITCODE -ne 0) { throw 'Azure CLI version check failed.' }
```

Azure CLIのバージョンが表示されることを確認します。本手順では`.bicepparam`を使用するため、**最新版のAzure CLIを使用してください**（`.bicepparam`のデプロイには2.53.0以降が必要です）。既にインストール済みの場合も、[インストール手順](https://learn.microsoft.com/ja-jp/cli/azure/install-azure-cli-windows)に従って最新版へ更新します。コマンドが見つからない場合はターミナルの開き直しとインストール状況を確認してください。

Bicep CLIは、Bicepを使うビルド・デプロイコマンドの初回実行時にAzure CLIが自動インストールします。

## 4. Azureへのログインとサブスクリプションを確認する

講師が指定した演習用サブスクリプションを使用します。

```powershell
az login
if ($LASTEXITCODE -ne 0) { throw 'Azure login failed.' }

az account set --subscription '<演習用サブスクリプションID>'
if ($LASTEXITCODE -ne 0) { throw 'Subscription selection failed.' }

az account show --query '{Name:name,SubscriptionId:id,TenantId:tenantId,State:state}' -o table
if ($LASTEXITCODE -ne 0) { throw 'Subscription lookup failed.' }
```

表示されたサブスクリプション名・ID・テナントが講師の指定と一致し、状態が`Enabled`であることを確認します。Portalでも同じアカウント・テナント・サブスクリプションを選びます。候補に出ない場合は講師へ連絡し、別のサブスクリプションへ勝手に変更しないでください。

Portalで初期構築する参加者は、Portalの **ディレクトリとサブスクリプション** で対象を確認します。

## 5. Azureの権限とクォータを事前確認する

参加者が、使用するサブスクリプションで以下を確認してください。不足する権限やクォータは開催前に申請します。

- **リソース作成・操作権限**：サブスクリプションの **アクセス制御（IAM）→ 自分のアクセス権の表示** で、リソースグループ作成・Bicepのサブスクリプションスコープのデプロイ・演習リソースの作成と削除・ASR操作を行える権限を確認します。標準ロールでは、サブスクリプションスコープの **共同作成者（Contributor）** が目安です。
- **ロール割り当て権限**：両リージョンのキャッシュストレージに、コンテナーのマネージドIDへの **共同作成者** と **ストレージ BLOB データ共同作成者** を割り当てられる権限を確認します。Contributorに加え、対象を含むスコープの **ユーザー アクセス管理者（User Access Administrator）** などが必要です。PIMを使う場合は、演習時に必要なロールを有効化できることも確認します。
- **リソースプロバイダーの登録**：Portalの **サブスクリプション → 対象サブスクリプション → リソースプロバイダー** で、`Microsoft.Compute`、`Microsoft.Network`、`Microsoft.Storage`、`Microsoft.RecoveryServices`、`Microsoft.Automation`の状態を確認します。未登録のものは選択して **登録** を実行し、`Registered`になったことを確認します。
- **vCPUクォータの空き**：Portalの **クォータ → Compute** で、Region A・Bそれぞれの **リージョンの合計vCPU数** と **VMファミリ別vCPU数** の使用量・上限を確認します。既定の`Standard_D2s_v5`は1台あたり2 vCPUで、対象はDSv5ファミリです。各リージョンで演習VMを起動できる空きが必要です。共有サブスクリプションでは、参加者数とテスト・復旧VMの同時起動分も含めて確保します。
- **リージョンとサービスの対応**：使用する両リージョンで`Standard_D2s_v5`、Ubuntu Server 22.04 LTS Gen2のTrusted Launch、ASR、Bastion Developerを利用できることを確認します。クォータに空きがあっても、実際のVM容量不足で作成できない場合があります。
- **Azure Policyなどの制限**：公開IPの作成、HTTP（80）のAnyからの受信、コンテナー・ストレージの公開サービスエンドポイントが許可されることを確認します。
- **演習IDの重複回避**：参加者・グループごとに異なる`exerciseId`を決めます。英小文字・数字・ハイフンの1～24文字で、先頭・末尾を英数字にします。Bicepを使う場合は[パラメータファイル](./infra/main.bicepparam)の`exerciseId`を自分の値へ変更し、同じサブスクリプション内の他の参加者や既存環境と重複しないことを確認します。

## 6. 端末からの通信を事前確認する

- **HTTPS通信**：使用するPCからGitHubとAzure Portalを開けること、Azure CLIでログインできることを確認します。Bicepを使うコマンドの初回実行時に必要な、Bicep CLIのダウンロード先への通信も許可されることを確認します。
- **演習用の接続経路**：端末・ネットワークの制限で、Bastionのブラウザー接続（HTTPS）と演習用公開IPへのHTTP（TCP 80）が遮断されないことを確認します。実際のBastion接続とWeb表示は、当日のVM作成後に確認します。
- **VMからの送信通信**：使用するAzure環境で、Ubuntuのパッケージ配布先と[ASRが必要とする宛先](https://learn.microsoft.com/azure/site-recovery/azure-to-azure-about-networking)への送信が許可されることを確認します。

## 準備完了後

当日、講師の案内に従って次のいずれかへ進みます。

- **Bicepで初期構築**：[Bicepによる初期リソースの作成](./00-Bicepによる初期リソースの作成.md)。パラメータ設定、what-ifによる確認、承認後のデプロイを行います。
- **Portalで初期構築**：[01：ネットワークとVMの作成](./01-ネットワークとVMの作成.md)。

BicepとPortalで同じ初期環境を二重に作成しないでください。Apacheの構成とASRの有効化以降は共通の手順です。
