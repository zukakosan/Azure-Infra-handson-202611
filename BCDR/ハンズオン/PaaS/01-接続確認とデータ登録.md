## このページの手順

### Step 1：構成と接続を確認する

1. Azure PortalでサーバーAの **フェールオーバーグループ（Failover groups）** を開き、配布されたグループを選択します。
2. 対象DB、Primary／Secondary、リージョン、切り替え方針、複製状態を確認します。
3. **読み取り／書き込みリスナー（Read/write listener endpoint）** の名前を控えます。
4. SQLクライアントでリスナー名と演習DB名を明示し、指定されたMicrosoft Entra認証で接続します。サーバーA個別の名前は使いません。
5. 次のSQLを実行し、接続先を記録します。

```sql
SELECT
    @@SERVERNAME AS ConnectedServer,
    DB_NAME() AS ConnectedDatabase,
    SYSUTCDATETIME() AS ObservedAtUtc;
```

**確認結果**：リスナー経由で演習DBに接続でき、初期Primaryへ接続していることをPortalの役割と照合できること。

対象DBの誤り、複製異常、Secondaryへの接続準備不足、権限不足があれば中止して講師へ連絡します。Azure RBACがあってもDBへログイン・書き込みできるとは限りません。

### Step 2：切り替え前のデータを登録する

次のSQLを実行します。自動コミットの状態で実行し、未完了のトランザクションを残しません。

```sql
INSERT INTO dbo.DrExerciseRecords (RecordId, ExerciseKey, Phase)
OUTPUT inserted.RecordId, inserted.ExerciseKey, inserted.Phase, inserted.CreatedAtUtc
VALUES (NEWID(), N'<自分の演習キー>', N'before-failover');

SELECT RecordId, ExerciseKey, Phase, CreatedAtUtc
FROM dbo.DrExerciseRecords
WHERE ExerciseKey = N'<自分の演習キー>'
ORDER BY CreatedAtUtc, RecordId;
```

**確認結果**：登録成功、RecordId、登録時刻を記録し、登録した行を再取得できること。

以後、[Step 4](./02-フェールオーバーと読み書き確認.md)までは新しい登録を止めます。登録のタイムアウトなどで成否が不明な場合は、先に一覧を照合します。結果を確認せずINSERTを繰り返すと、同じ操作の行を重複登録し得ます。
