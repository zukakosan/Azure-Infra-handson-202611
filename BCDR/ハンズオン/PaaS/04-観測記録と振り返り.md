## 6. 観測記録

時刻はUTCなど同じタイムゾーンに統一します。ログのイベント時刻と画面で確認した時刻を区別し、未取得の値を推測で埋めません。

| 項目 | 記入欄 |
|---|---|
| Failover Group／DB／リスナー名 |  |
| 切り替え前後・復帰後のPrimary／接続先 |  |
| 切り替え前のRecordId・時刻／切り替え後の確認 |  |
| 切り替え後のRecordId・時刻／復帰後の確認 |  |
| t0：計画フェールオーバー操作開始 |  |
| t1：Portalで役割変更の成功を確認 |  |
| t2：リスナー経由の最初の読み取り成功 |  |
| t3：登録・再取得と3回連続確認の完了 |  |
| t3－t0／接続失敗の時刻・内容・回数 |  |
| フェールバックの開始／読み書き確認完了 |  |
| 復帰後の複製状態／未確認事項／証拠への参照 |  |

`t3－t0`は、**計画切り替えの操作開始から今回のDB検証完了までの時間**です。障害検知、判断・承認、Webアプリ、利用者経路などを含む業務全体のRTOではありません。

計画フェールオーバーで登録済みデータが残った結果から、強制フェールオーバーのRPOをゼロと結論付けません。通常のリージョン間複製は非同期であり、強制切り替えでは未複製データを失う可能性があります。基本演習のRPO評価は「計画切り替えで対象データの保持を確認、実障害時の損失は未検証」と記録します。

## 7. よくある問題と中止条件

| 状況 | 確認・対応 |
|---|---|
| 切り替え操作ができない | 現在の役割、複製の準備、両サーバー・グループへのAzure RBACを確認 |
| Portalは成功、SQL接続は失敗 | リスナー名、DNS、既存接続、Firewall、Private Endpoint、認証を確認 |
| 接続できるが書き込めない | 読み取り専用リスナーや旧Primaryへの接続、DB内のINSERT権限を確認 |
| 行が見つからない | DB名、演習キー、RecordId、INSERTの成功・コミットを確認。確認前に再登録しない |
| Secondaryが異常／同期できない | 演習を中止し、強制切り替えで代替しない |
| 本番・他グループのDBが含まれている | 操作前に中止する。Failover Group内のDBはグループとして切り替わる |

## 8. 完了条件と振り返り

- [ ] 構成、切り替え方針、複製状態、リスナーを記録した。
- [ ] 計画フェールオーバーでPrimary／Secondaryの交換を確認した。
- [ ] 同じリスナーで再接続し、切り替え前のデータ参照と新規登録を確認した。
- [ ] 計画フェールバック後も、切り替え先で登録したデータを確認した。
- [ ] 元の役割、読み書き、両系の複製正常性を確認した。
- [ ] 計画切り替えの検証を、実障害時のRTO／RPO保証と区別できる。

次に考えること：

1. WebアプリがRegion Aだけにある場合、DBをRegion Bへ切り替えれば業務は再開できるか。
2. 書き込み中の接続が切れ、成否が不明だった場合、再試行で二重登録を防ぐには何が必要か。
3. 誤更新がSecondaryにも複製された場合、過去の正常な状態へ戻すには何が必要か。

## 9. 発展課題とPaaSサービス比較

強制フェールオーバーは、データ損失の許容、承認、専用環境、復旧手順を別途決めた場合に限ります。基本演習の追加ボタン操作として実施しません。

| サービス例 | 比較したいDRの観点 |
|---|---|
| Azure SQL Database | 計画／強制切り替え、非同期複製、リスナー、再接続 |
| Azure Storage | 冗長化方式、副リージョンからの参照可否、アカウント切り替えの対応条件・損失可能性 |
| Cosmos DB | 複数リージョン配置、書き込み方式、整合性、クライアント設定 |
| App Service＋Front Door | アプリの複数配置、依存先、正常性判定、利用者の入口 |

各サービスのオプション、対応条件、RTO／RPO、費用は別々に確認します。データ切り替えとアプリ・入口の切り替えを組み合わせた業務試験は追加演習とします。

## 10. 費用・未確定事項・参考資料

Primary／SecondaryのDB、ネットワーク、接続基盤などに費用が発生します。切り替えで課金が止まるわけではありません。演習後は担当者が残存リソースと課金を確認します。

実施前に確定する事項：リージョン・サービス階層、SQLクライアント、Entra認証、ネットワーク、役割分担、再接続間隔・待機上限、費用見積もり、最終削除の担当。
