# Azure ルーティング設計・トラブルシューティング ワークショップ

## 1. 概要

- **想定時間**: 3時間20分（座学60分、休憩10分、ハンズオン130分）
- **対象者**: Azureの基本操作とVNetの基礎を理解しているインフラ／クラウド担当者
- **形式**: 講義、デモ、ハンズオン、障害解析チャレンジ
- **主なサービス**: Azure Virtual Network、VNet Peering、Route Table、UDR、Azure Firewall、Network Watcher、（クラス共用デモ）VPN Gateway（BGP）

## 2. 到達目標

ワークショップ終了後、受講者が以下を実施できることを目標とする。

- Azureにおけるパケット転送とルート選択の仕組みを説明できる
- システムルート、VNetピアリング、UDRの役割を理解できる
- Hub-Spoke構成で、UDRにより通信をAzure Firewallへ集約し、NVAを使う場合との設定上の違いを説明できる
- BGPの広告・学習とSpokeへの経路伝達を区別し、GatewayとNICの両方で経路を確認できる
- Network Watcherを使って、疎通障害の原因を切り分けられる
- 指定HTTPSサイトと隣のSpoke VMに接続できない環境で、FWアプリケーションルールの許可先FQDN誤りと隣のSpokeの戻りUDR欠落を調査し、1つずつ修正・再試験できる
- 非対称ルーティングやNSGによる通信遮断の典型例を説明できる

### 4.1 Azureルーティングの基礎

- Azure上でルートが決まるまでの流れ
- システムルート
- ユーザー定義ルート（UDR）
- BGPから伝播されたルート
- ルート選択の優先順位
  - 最長プレフィックス一致
  - UDR、BGP、システムルートの関係
- ネクストホップの種類
  - `VirtualAppliance`
  - `VirtualNetworkGateway`
  - `VnetLocal`
  - `Internet`
- NIC、サブネット、VNet間でのパケットの流れ

- VNetピアリング

- 非対称ルーティングが発生する典型例
- Azure Virtual WAN／Azure Route Serverの位置付け

### 4.3 トラブルシューティング

- NICの有効なルート
- Network Watcher
  - Connection troubleshoot
  - Next hop
  - NSG diagnostics（ICMP／TCPの許可・拒否と適用ルール）

  - Network topology
  - Packet capture

事前課題（構築担当者）：[Bicepによる参加者ごとの環境のデプロイ](./ハンズオン/Lab_01/00-事前環境のデプロイ.md)。授業直前に参加者分を展開し、開始状態の確認を完了する。展開開始から削除完了まで約4時間以内を目安に管理し、以下のハンズオン130分には含めない。

本文・事前準備は[ハンズオンの進め方](./ハンズオン/00-NWハンズオンの進め方.md)を参照する。FW演習は参加者ごとの独立したAzure Firewall環境、BGPデモはFWを置かない講師専用の独立環境を使用する。VPN Gatewayは専用RGに2台だけ講師が事前展開し、受講者は広告・学習・経路を観測する。初稿ではAzure Firewallを基準とし、NVAへの置き換えは別教材とする。

1. [Hub-SpokeとUDR](./ハンズオン/Lab_01/01-Hub-SpokeとUDR.md)：参加者ごとの環境でピアリング、FW折り返し、直接経路を比較
2. [BGPデモ：経路広報と確認](./ハンズオン/Lab_02/02-BGPによる経路広報と確認.md)：FWとは独立した講師専用環境で広告・学習・経路伝達を観測

### 5.1 演習の目的

参加者ごとのHub-Spoke構成において、Spoke間通信を自分のAzure Firewallへ転送する往復経路を構成する。UDRなし・直接ピアリング・具体的なUDRの違いを比較し、有効なルート、Next hop、ping（ICMP）、FWログで確認する。HTTPサーバー起動は基本演習に含めず、基本演習のTCP 8080試験は待ち受けサービスを事前準備した場合だけの任意課題とする。障害解析は別途用意する外向きHTTPS構成で、指定URLへのTCP 443接続を調査する。BGPはFW演習と分離した講師専用のVPN Gateway環境で、広告・学習とSpokeへの経路伝達を観測する。BGP環境の準備・切り替えは講師が行い、受講者は読み取りのみとする。参加者ごとのFW環境とは接続しない。

### 5.2 演習環境

```text
参加者ごと：FW演習（専用Hub・Azure Firewall・Spoke×2。VPN Gatewayなし）
Spoke 1 ── VNet Peering ── Hub + Azure Firewall ── VNet Peering ── Spoke 2

講師デモ専用：BGP観測（講師が事前展開・操作、受講者は読み取りのみ）
デモ用Spoke ── VNet Peering / Gateway Transit ── BGP Hub + VPN Gateway
                                                   ║ VNet-to-VNet VPN / BGP
模擬オンプレミス ─────────────────────────── VPN Gateway 2
```

図のHub-Spoke / Firewallは参加者ごとの環境で、VPN Gatewayを配置しない。BGPデモ環境は専用リソースグループへ講師が事前展開し、操作・復元・削除も講師が行う。受講者はピア状態、Gatewayの広告・学習ルート、Spoke NICの有効ルート、疎通を観測する。Firewall演習用VNetとは接続しない。

### 5.3 演習手順

1. 自分の環境でHub・Spokeの範囲、VMの試験サービス、FWの状態を確認する
2. Hub-Spokeの相互ピアリング後、状態が両方向とも`Connected`であることを確認する
3. 直接SpokeピアリングもUDRもない状態で、Spoke間の経路が存在せずpingが失敗することを確認する
4. 往復UDRを関連付け、両VMの相手宛てNext hopがFWの`VirtualAppliance`であることを確認する
5. 両方向のping疎通とFWのICMP `Allow`ログを確認する
6. 一時的な直接Spokeピアリングで、直接経路・`/0`UDR・具体的`/16`UDRのNext hopがどう変わるかを確認する
7. 直接ピアリングと一時UDRを削除し、両方向のFW経由通信が復旧したことを確認する
8. 講師デモでBGPピア状態、両方向の広告・学習経路、Spoke NICの有効ルートを観測する
9. 講師によるSpokeの経路伝達切り替え前後で、BGPピア状態、経路、模擬側VMとの疎通を比較する。受講者は設定を変更しない

### 5.4 期待結果

- Spoke間通信が往復とも意図したAzure Firewallを経由する
- 送信元VMのNICで、対象プレフィックスのネクストホップが`VirtualAppliance`として表示される
- Network WatcherのNext hopで、想定した次ホップが確認できる
- Firewall側で対象ICMP通信のログが確認できる
- 直接ピアリングがある場合、`/0`UDRだけではFWを経由しない理由を説明できる
- BGPの広告・学習と、Gateway Transit／経路伝達によるデモ用Spokeへの適用を区別して説明できる

## 6. 障害解析チャレンジ

「Spoke 1のVMで作業中、`https://www.microsoft.com/` に接続できないことが分かった。さらに隣のSpoke 2 VMへのpingも応答がない。設計上、外向き通信もSpoke間通信もHub Firewall経由で、両VMのBastion接続は使える」という状況から開始する。参加者ごとのFW環境に、**FWアプリケーションルールの許可先FQDN誤りとSpoke 2の戻りUDR欠落の2つを同時に含む構成**を講師がBicepで用意する。受講者自身による障害注入は行わない。受講者向けの課題、段階的ヒント、提出用シートは[障害解析とAI活用](./ハンズオン/Lab_03/03-障害解析とAI活用.md)を参照する。ハンズオンフォルダー内の資料はそのまま配布できる受講者向け手順書とし、障害設定や授業運営の準備事項は本アジェンダで扱う。

### 6.1 設定するミス（講師用・調査終了後に公開）

1. **FWの許可先FQDN誤り**：対象VMからのHTTPS 443を許可するアプリケーションルールの宛先FQDNを、正しい`www.microsoft.com`ではなく`www.example.com`にする。送信元・プロトコル・ポート・Allowアクションは正しいままにする。NSGのTCP 443送信は許可し、接続先に一致するFW許可ルールがなく既定で拒否される状態とする。
2. **隣のSpokeの戻りUDR欠落**：Spoke 2の`rt-spoke2`で`to-spoke1-via-fw`（`10.1.0.0/16 → FW実IP`）だけが存在しない。サブネットのRT関連付けは維持する。Spoke 1の外向き・Spoke 2宛てUDRと関連付けは正常に保つ。

基本演習は[演習01用Bicep](./ハンズオン/Lab_01/bicep/README.md)で初期構築する。障害解析は、その専用RGへ[演習03用Bicepのデプロイスクリプト](./ハンズオン/Lab_03/bicep/README.md)を適用する。既存のVM・FW・NSGを再利用し、ピアリング、ルートテーブル・サブネット関連付け、FWルールを演習03の状態へ更新する。初期構築直後でも、演習01完了後でも適用できる。実機予行では一度修正して次の正常構成とHTTPS・Spoke間双方向pingの記録を保存し、その後03用を再適用して開始状態へ戻す。

- FWの公開IPによる外向き通信とSNATを使用し、送信元を対象VMに限定したアプリケーションルールで`www.microsoft.com`へのHTTPS 443を許可する。外部IPを固定せず、FQDNで許可する。正常なDNS、TLS証明書検証、HTTP 2xx／3xx応答を実機で確認する。サイトが利用できない場合は承認済みの検証先へ教材・許可ルールを揃えて変更する。
- Spoke 1では`0.0.0.0/0 → FW実IP`と`10.2.0.0/16 → FW実IP`を同じRTに保持し、サブネットへの関連付けを維持する。初期構築時の既定送信アクセス無効を維持し、VMの公開IP、NAT Gateway、Load Balancerの送信規則など、FWを迂回するインターネット送信経路は追加しない。
- DNS解決、ピアリング、NSGのTCP 443送信許可、FWの既存ICMP Allow、Spoke間ICMPのNSG許可、OSのICMP応答、管理経路は正常に保つ。プライベートIP間はSNATしない。直接Spokeピアリングは残さず、Spoke 2には復路を代替する`/0`UDRや他の経路を追加しない。Bastionの管理接続がFWルール誤りや復路欠落の影響を受けないことも確認する。
- VMに`curl`、`getent`と信頼済みCA証明書が利用可能であることを事前確認する。試験はIPv4、プロキシ不使用、リダイレクト自動追跡なしの同じURLに固定する。DNSによる接続先IPの変化を記録し、NSG・Next hopは実際の接続先IPで評価する。
- 演習03用Bicepは`rcg-lab`をICMP許可とFQDNが誤ったHTTPS許可へ更新し、Spoke 2のRTに`routes: []`を明示して、演習01で作成した戻りUDRも除去する。対象HTTPSを許可する別のNetwork rule、Application rule、継承ルールやワイルドカードがなく、誤りが隠れないことを確認する。スクリプトは継承Policy、別のルールグループ、直接Spokeピアリングなどを検出したら停止する。ルート一覧・サブネット設定は既定の演習環境向けに上書きするため、独自設定を追加したRGへ適用しない。NSG自体・VM・FW本体・診断設定は変更しない。適用後に設定ミス2点をCLIで確認する。正常構成と復元手順を保存し、参加者が修正した後は演習03用Bicepを再適用しない。

予行では次の全状態を確認する。Spoke 1から外部IP・Spoke 2へのNext hopは全段階でFW実IPの`VirtualAppliance`、NSGの対象TCP 443送信評価はAllowとする。Spoke 2からSpoke 1へのNext hopは復路UDR欠落時に`None`、復元後はFW実IPの`VirtualAppliance`を確認する。これは別経路を通る非対称ルーティングではなく「復路なし」の障害である。

| 状態 | FWの許可先FQDN | 同じURLへのHTTPS | Spoke 2→Spoke 1のNext hop | Spoke間ping |
|---|---|---|---|---|
| 初期：2つのミスが残る | `www.example.com`（誤り） | 失敗 | `None` | 失敗 |
| FWのFQDNだけ修正 | `www.microsoft.com` | 成功 | `None` | 失敗 |
| Spoke 2の復路UDRだけ復元 | `www.example.com`（誤り） | 失敗 | `VirtualAppliance`、FW実IP | 両方向成功 |
| 両方を修正 | `www.microsoft.com` | 成功 | `VirtualAppliance`、FW実IP | 両方向成功 |

HTTPS成功はTLS検証と正常時と同様のHTTP 2xx／3xx応答で確認する。症状ごとに原因が異なり、片方の修正で片方だけが復旧することを確認する。

### 6.2 受講者の進め方

- 冒頭で「指定HTTPSサイトにも隣のSpoke VMにも接続できない」という状況とFW経由の期待構成を共有する。原因・件数・障害設定用Bicepの差分は解説まで伏せる。
- 自由調査15分を目安に、Portal、Cloud Shell／Azure CLI、Network Watcher、VM内のコマンドからツールと確認順序を選ぶ。
- 必要に応じた段階的ヒントと原因整理に8分、各自の判断による修正・再試験に12分、共有・解説に5分を目安とする。修正・再試験にはFW Policyの反映待ちを含む。参加者専用FW環境内の修正は、変更のたびに講師の確認を必要としない。
- VM内の名前解決・`curl`とSpoke間pingで症状を再現し、有効なルート・Next hopで外向き経路とSpoke間の往復経路を調べる。NSG diagnostics／IP flow verifyのAllowだけで全体を正常とせず、FWに関連付くPolicyのアプリケーションルールを開き、送信元・HTTPS 443・許可先FQDNを設計と照合する。FWログなしでも設定の不一致と修正後の再試験で確認できる構成とする。Connection troubleshootのTCP診断は追加確認とし、TLS・HTTPの最終確認は`curl`で行う。
- 1つずつ修正し、各変更後にHTTPSとSpoke間pingの両方を再試験する。片方が復旧してももう片方は失敗することを確認し、共通の原因だと決めつけない。調査・修正の順序自体は固定しない。
- 最後に外部IP宛てNext hop、TCP 443送信のNSG Allow、FW Policyの対象FQDN許可、同じURLへのHTTPS応答、管理接続とSpoke間の往復経路・両方向pingを確認する。FWログは診断設定・LAW・権限が準備済みで時間がある場合のみ任意とし、取り込み待ちやログ取得は完了条件に含めない。

Copilot in AzureのTroubleshooting Agentを利用できる場合は、調査・原因整理の中で対象VMと症状を指定して診断を依頼し、提示された証拠・原因候補・未確認事項を手動調査と比較する（最大5分）。診断範囲はリソース種別・権限・利用可能なデータに依存するため、UDR・NSG・FWを含む経路全体の自動特定を前提としない。エージェントによる設定変更やサポート要求の送信は行わない。利用できない場合も手動調査で演習を完了する。

- Azure Portalを操作できること
- VNet、サブネット、NSGの基本知識
- 必要に応じてAzure Cloud ShellまたはAzure CLIを利用できること
- RDP／SSHを使用する場合の接続環境

### 7.2 講師

- 参加者ごとに専用リソースグループ、Hub-Spoke、テストVM、Azure Firewall、Firewall Policy、Log Analytics診断設定を展開し、各自が操作する
- [BGPデモ用Bicep](./ハンズオン/Lab_02/bicep/README.md)で専用RGへ3 VNet、BGP対応VPN Gateway 2台、VM 2台、Bastion Developerを事前展開する。参加者環境とは接続せず、Firewallを配置しない
- BGPの広告・学習・Spoke経路伝達について、受講者へ見せる正常時と切替時の実測値。設定変更・復元は講師が行う
- 全VMのping利用・ICMP応答設定、演習VM間のICMPのNSG・OS・FW許可、UDR変更後も使える管理経路。TCP 8080試験サービスとTCP許可は任意課題を実施する場合だけ準備
- [演習03用Bicep](./ハンズオン/Lab_03/bicep/README.md)の適用・実機予行、正常構成への復元手順。FWアプリケーションルールの許可先FQDN誤りとSpoke 2の復路UDR欠落が同時に存在し、それぞれの修正で対応する通信が復旧することを確認する。FW Policy反映時間を含めて40分枠を予行し、追加の反映待ちが必要なら共有・解説と並行する。詳細は第6節を参照
- 正常時の記録後、講師デモの終了までに自分専用FW環境への障害設定を適用できる運営手順。受講者には症状だけを提示し、段階的ヒントと解説を後から公開する
- リソース削除手順

## 8. 運営上の注意

- Azure Firewallはプロビジョニングに時間とコストがかかるため、原則として事前展開する
- BGPデモ用VPN Gateway 2台と3 VNet環境を専用RGへ事前展開する。BGPデモ環境は講師が管理し、受講者は読み取りのみとする
- 130分のハンズオン枠ではFW／VPN／VMの新規展開を行わず、ピアリング・UDR・伝達設定と観測に集中する
- 通常演習の各手順に「正常時の期待結果」を記載する。障害解析は正常時の記録を渡し、調査手順・原因を先に示さず自由調査から始める
- 参加者ごとのFirewall演習環境と講師専用BGPデモ環境を分離して用意し、BGP環境の変更は講師に限定する
- Azure Firewallなどの課金対象リソースを含むため、展開開始から削除完了まで約4時間以内を目安に管理し、演習終了後すぐ専用RGを削除する。VM停止だけでは課金は止まらない
