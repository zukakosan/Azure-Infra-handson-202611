# 演習03：障害解析用の構成をデプロイする

[障害解析とAI活用](../03-障害解析とAI活用.md)の開始状態を、参加者ごとの専用リソースグループへ適用します。構成には演習用の設定ミスが含まれます。原因を自分で調べたい場合は、デプロイ後にBicepのソースや差分を正解として参照せず、手順書の状況設定から調査を始めてください。

## 1. 使用する環境

- [演習01用Bicep](../../Lab_01/bicep/README.md)で作成した、自分専用のFW演習環境を使用します。演習01を完了していなくても、初期構築の完了後に適用できます。
- 空のRGへこのテンプレートだけをデプロイすることはできません。別のRGで演習03を実施する場合も、そのRGに演習01用の初期環境を先に作成してください。別環境はFW・VMなどの費用が追加で発生します。
- 既存のVM・Bastion・Firewall・NSG・Log Analyticsを使用します。VMやFWの再作成、パスワードの再入力、BGP環境の変更は行いません。
- 対応する名前・アドレスは演習01の既定構成です。実運用環境、名前・アドレスを変更した環境、独自のルート・NSG・FW設定を追加した環境には適用しないでください。
- 一時的な直接Spokeピアリングは、演習01の手順に従って両方向とも削除してください。既存のHub-Spokeピアリングは名前を自動取得して再利用し、まだなければ作成します。
- ルートテーブルのルート一覧、VMサブネットの設定、FW Policyの`rcg-lab`内のルール一覧を演習03用に上書きします。元に戻す必要がある設定は事前に記録してください。その他のFWルールグループがある環境はスクリプトが停止します。

FWログは任意です。このデプロイは診断設定を追加・変更せず、既存のLAWを使用できる場合もログ表示を待つ必要はありません。VMで`curl`、`getent`、`ping`とCA証明書を利用できることを確認してください。

## 2. 対象を確認してデプロイする

Azure CLIとBicep CLIが使用でき、Azureへログイン済みであることを確認します。自分専用環境のVNet・サブネット・ピアリング・ルートテーブルとFirewall Policyのルールを変更できる権限が必要です。

リポジトリルートのPowerShellで実行します。サブスクリプションIDとRG名は、自分に割り当てられた値へ変更してください。

```powershell
az login
if ($LASTEXITCODE -ne 0) { throw 'Azure login failed.' }

az account list --output table
if ($LASTEXITCODE -ne 0) { throw 'Subscription lookup failed.' }

.\Network\ハンズオン\Lab_03\bicep\Deploy-Lab.ps1 `
    -SubscriptionId '<演習用サブスクリプションID>' `
    -ResourceGroupName 'rg-nw-01'
```

スクリプトは対象サブスクリプション・RGを明示して、既存VNetのアドレス、FWのPolicy、既存ピアリングを確認します。その後、ローカルビルド、Azure側の検証、`what-if`を実行します。リージョンは既存Hubから取得します。

1. 表示されたサブスクリプションとRGが自分専用環境であることを確認する。
2. `what-if`で変更対象を確認する。VM・Bastion・FW本体・共用BGP環境の作成・削除は予定していない。
3. 確認入力に対象RG名を正確に入力すると適用が始まる。それ以外を入力した場合はデプロイしない。
4. `nw-troubleshooting`のデプロイが`Succeeded`になるまで待つ。更新中に同じデプロイを並行実行しない。

失敗した場合はAzure Portalの対象RG →「デプロイ」→ `nw-troubleshooting` → 操作の詳細で確認してください。失敗時も一部設定が変更済みの場合があります。`Complete`モードへの変更や、原因を確認しない再実行は行わないでください。

## 3. 演習を開始する

1. 出力`firewallPrivateIp`、`sourceVmId`、`destinationVmId`、`targetUrl`を記録する。
2. 4方向のHub-Spokeピアリングが`Connected`で、両Spoke VMへ各VNetのBastionで接続できることを確認する。
3. [障害解析とAI活用](../03-障害解析とAI活用.md)の冒頭の状況設定を読み、HTTPSとSpoke間pingをVM内から試す。

このテンプレートは**正常構成への復元用ではありません**。再適用すると、修正済みの設定も演習開始状態へ戻ります。復旧は演習手順に従って自分で行い、演習終了後は専用RGの削除期限と費用を確認してください。VM停止だけではFirewallなどの課金は止まりません。

## ファイル

| ファイル | 用途 |

| [main.bicep](./main.bicep) | 既存の演習環境へ演習03の経路・ピアリング・FWルールを適用 |
| [main.bicepparam](./main.bicepparam) | Bicep CLIによる個別ビルド用の既定パラメーター |

デプロイスクリプトは既存環境から取得した値を`main.bicep`へ直接渡します。`main.bicepparam`はスクリプトでは読み込みません。
