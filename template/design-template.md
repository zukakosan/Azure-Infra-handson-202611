# スライド デザインガイド

## 1. 適用範囲

このガイドは、指定されたPowerPointテンプレートを使って
スライドを作成・修正・再生成する場合に適用する。

## 2. 優先順位

1. 今回の個別指示
2. 本デザインガイド
3. PowerPointテンプレートのブランド要素と視覚的な基準
4. 生成ツールの既定値

ガイドとテンプレートが矛盾する場合は、該当箇所を示して確認する。
テンプレートの既存レイアウトをそのまま使うことより、ブランド要素を保ちながら内容に適した情報設計を行うことを優先する。

## 3. テンプレートの扱い

- 元のPPTXは変更しない。
- テンプレートは固定レイアウトではなく、スライドサイズ、テーマカラー、ロゴ、フッター、ページ番号、罫線、余白の基準を確認するために使用する。
- 本文スライドの構成とレイアウトは、説明する内容に適した情報設計を優先して新規に作成してよい。適切な既存レイアウトがある場合は再利用する。
- マスター、ロゴ、フッター、ページ番号を維持する。既存の罫線や余白は視覚的な基準として参照し、本文構成に合わない場合は同じテーマの範囲で調整してよい。
- ページ番号は右下に配置する。テンプレートで別の位置にある場合は、書式を維持したまま右下へ移動する。
- 表紙や章扉は、既存のものを維持し、必要性が明確でない限り追加しない。
- 装飾は情報の階層、分類、順序、強調を明確にする目的に限定し、内容と関係のない装飾は追加しない。

## 4. フォント

- 日本語および英数字には、原則として `Yu Gothic UI` を使用する。
- PowerPointテンプレートで別のフォントが明示的に設定されている箇所は、その設定を維持する。
- 新しく追加するテキストには `Yu Gothic UI` を設定するが、既存要素のフォントを一括置換しない。
- コードおよびコマンドには `Consolas` を使用する。
- フォントが利用できない場合は、置換前に確認する。
- 本文は16pt未満にしない。
- 補足や注意書きは12pt未満にしない。
- スライド下部の出典は10pt未満にしない。
- 文字を収めるための過度な自動縮小は禁止する。

## 5. 本文

- 本文で複数の情報を並列に示す場合は、原則として `・` を行頭に付けた箇条書きを使用する。
- 箇条書きは1項目につき1つの要点を基本とし、各項目だけを読んでも意味が通る文にする。
- 用語の定義、前提、結論など、連続した文章の方が理解しやすい箇所は無理に箇条書きへ分割しない。
- 箇条書きにするために本文を名詞の羅列へ短縮したり、意味のある条件や留保を削除したりしない。
- 箇条書きの階層は原則1段とし、入れ子が必要な場合は内容の分割または図表化を検討する。

## 6. 言葉遣い

- 技術的な対象、主体、動作、条件、結果を具体的に書く。
- 読み手への呼びかけ、比喩、情緒的な表現より、事実、操作、関係、判断基準を優先する。
- タイトルは、そのスライドで説明する製品、機能、構成、処理、比較対象を具体的に示す。
- タイトルだけを読んでも説明対象が分かるようにし、本文を読まなければ意味が確定しない指示語や抽象語を使わない。
- 「実現する」「支える」「つなぐ」「加速する」「変革する」などの語は、何がどのように変わるかを具体的に説明できる場合に限って使用する。
- 製品や機能の効果を述べる場合は、適用条件と根拠を示し、効果を断定または誇張しない。
- 初出の略語や専門用語は正式名称または短い説明を添え、独自の言い換えを作らない。
- 同じ対象は資料内で同じ名称を使い、意味のない言い換えで表現を揺らさない。
- 一文を長くしすぎず、複数の主張や条件を含む場合は文または箇条書きを分ける。
- 体言止めを連続させず、動作や関係を説明する箇所では述語まで書く。

### 避ける表現と書き換え例

| 避ける表現 | 書き換え例 |
| --- | --- |
| デバイスとクラウドをつなぐ架け橋 | IoT Hubは、デバイスとクラウドアプリ間のメッセージを中継する |
| データが新たな価値を生み出す | 収集したテレメトリを分析し、設備の異常検知に使用する |
| 運用を次のステージへ | デバイスの状態確認と設定変更をクラウド側から行う |
| この仕組みがビジネスを加速する | 自動処理により、担当者が手作業で確認する回数を減らす |
| 安全な接続を実現する | X.509証明書を使用してデバイスを認証し、TLSで通信を保護する |
| 柔軟な連携を支える | メッセージルーティングにより、条件に応じて配送先を分ける |

## 7. リンク

- 本文中では番号で参照し、スライド下部には対応する出典番号と完全なURLのみを表示する。
- AI生成スライドの事実確認を容易にするため、URLは省略せず表示する。
- クリック可能なハイパーリンクは、表示したURL文字列のみに設定する。出典番号には設定しない。
- URLが1行に収まらない場合は、URLを省略せず、パスの区切りなど意味を損なわない位置で折り返す。
- 出典欄を確保できない場合は、文字を10pt未満へ縮小せず、本文またはスライドの分割を検討する。
- 1スライドの出典は原則3件以内とする。3件を超える場合は、主張の統合またはスライドの分割を検討する。

### 出典の表示例

本文：

```text
IoT Hub は MQTT、AMQP、HTTPS をサポートする。[1]
```

スライド下部：

```text
[1] https://learn.microsoft.com/ja-jp/azure/iot-hub/iot-hub-devguide-protocols
```

- URL短縮サービスは使わない。
- Microsoftの情報は、利用可能な場合は日本語の公式ページを優先する。
- ローカルファイルへのリンクは外部配布版に残さない。
- ローカルファイルへのリンクが原稿にある場合は削除せず、配布先からアクセス可能なリポジトリURLなどへ置き換える。
- 置換先が不明な場合は確認する。


## 8. 出典

- 出典は根拠となる説明と同じスライドに置く。
- 技術的な主張には、対応する出典番号を該当する文の末尾に付ける。
- スライド下部では、第7章の表示形式に従って出典番号と完全なURLのみを表示する。
- 完全なURLは講師ノートにも記録する。
- 技術仕様、顧客前提、作成者の提案を区別する。
- 1つの番号に複数URLを割り当てない。
- 同じURLを同じスライド内で重複して掲載しない。

## 9. 色と強調

- 色はテンプレートのテーマカラーを使用する。
- 強調色は結論、注意、選択対象に限定する。
- 色だけで状態や分類を区別しない。
- 警告、参考情報、説明用の例は同じ書式にしない。
- 同じ枠や同じ配色を全スライドへ機械的に反復せず、資料全体ではテーマを統一しながら、各スライドでは内容に合う視覚的な強弱を付ける。

## 10. 図表

- 図、表、矢印、ラベルは編集可能なPowerPoint要素で作る。
- 同じ意味の要素には同じ色と図形を使う。
- 処理はフロー、比較は表、階層はツリーを基本とする。
- Mermaidでシーケンス図が指定されている場合は、参加者、メッセージ、順序、活性区間、注釈を維持する。
- Mermaidの図は、原則として編集可能なPowerPointの図形、線、テキストとして再構成する。
- Mermaidの描画画像をそのまま貼り付けて代替しない。
- シーケンス図がスライド幅に収まらない場合は、文字を縮小する前に図の分割を検討する。
- 本文と同じ情報を図中に重複掲載しない。

## 11. 禁止事項

- テンプレートのテーマから外れるグラデーションや、情報の理解に寄与しない装飾を追加しない。
- すべての情報を同じ大きさの箱へ収める、同じ分割レイアウトを連続させるなど、内容と無関係な画一構成を使用しない。
- 出典をノートだけに置かない。
- 本文を名詞の羅列へ短縮しない。
- 本文を収める目的で意味のある条件や留保を削除しない。
- テキストや図表を画像として貼り付けない。

## 12. 検証

- PowerPointで全スライドを再描画する。
- 文字切れ、重なり、フォント置換、余白を確認する。
- ページ番号が全スライドの右下にあり、本文、出典、フッターと重ならないことを確認する。
- すべてのリンクについて、表示したURL文字列にのみハイパーリンクが設定され、クリックできることを確認する。
- 表示されているURLと、設定されたハイパーリンク先が一致することを確認する。
- 本文中のすべての出典番号に、同じスライド内の対応する出典があることを確認する。
- 未参照の出典、重複した出典番号、同一スライド内で重複するURLがないことを確認する。
- PDFへ変換した場合もハイパーリンクが維持されていることを確認する。
- ノートに完全なURLがあることを確認する。
- タイトルだけを一覧で読み、各スライドの説明対象と順序が分かることを確認する。
- 比喩、呼びかけ、抽象的な効能、根拠のない断定が残っていないことを確認する。
- テンプレートのブランド要素が維持され、各スライドの構成が説明内容に適していることを確認する。
- 情報の優先順位が文字サイズ、配置、余白、図表によって判別でき、同じ構図の不必要な反復がないことを確認する。
- 修正したスライドは再描画して再確認する。
